# 清单 · 演示（demo-only）注入面总核对（指令66 A5）

> 目的：把全部 demo-only 注入面列全，逐项核对「生产恒忽略」机理与
> audit-online 伪造注入断言覆盖。生产恒忽略的总闸门只有一个：
> `lib/demo.ts isDemoAllowed()`——生产（VERCEL_ENV=production 或
> NODE_ENV=production）且未显式设 NEXT_PUBLIC_ALLOW_DEMO=1 时恒
> false。所有注入面都在闸门之后才被读取（见逐项机理列）。

## 注入面清单

| # | 注入面 | 入口与读取点 | 生产恒忽略机理 | audit-online 伪造断言覆盖 |
|---|---|---|---|---|
| 1 | `demo_role` Cookie（演示角色 owner/partner/staff） | `lib/data.ts getCurrentUser`：无 Supabase 会话时读 demo_role 定角色并置 user.demo=true | 读取前先过闸门：`if (!isDemoAllowed())` 直接返回匿名 staff（demo=false），生产永不读该 Cookie；有真实会话时更先走 profiles 真实角色 | §3：伪造 demo_role+demo_biz 访问 /、/salary → 307 ✓；§6(i)（66-A5 增）：带伪造 Cookie 的 /login 仍 200 且「演示」0 次 ✓ |
| 2 | `demo_biz` Cookie（演示业务授权 all/aihuishou/none） | `lib/data.ts getMyBusinesses` 演示分支、`components/Nav.tsx` demo-bar 读 demo_biz | 仅 `user.demo=true` 才进演示分支；真实/匿名用户在分支前 return（授权为空）。user.demo 的产生受 #1 闸门控制 | 与 #1 同请求覆盖（§3 伪造请求恒带 demo_biz=all）✓；单独 demo_biz 无 demo_role 时 getCurrentUser 仍走闸门后默认路径，生产恒匿名 → 307（§3 路径同理） |
| 3 | `demo_targets` Cookie（59-A2，base64url JSON 目标数组） | `lib/data.ts getSiteTargets`：`if (user.demo)` 分支内读 Cookie 注入示例目标，供复盘三分支回归 | 分支前提 user.demo=true，受 #1 闸门控制；生产 getCurrentUser 永不返回 demo 用户，分支恒不达。解析带逐字段校验，格式不对按未设定 | §6：伪造（role+biz+targets）访问 /、/business/aihuishou/reports → 307 ✓；§6(ii)（66-A5 增）：仅 demo_targets（无 demo_role）访问 /reports → 307 ✓ |
| 4 | 登录页演示入口 / 顶栏 demo-bar 与角色·业务切换器（DemoRoleSwitcher / DemoBizSwitcher） | `app/login/page.tsx` 以 isDemoAllowed() 决定渲染；`components/Nav.tsx` demo-bar 以 user.demo 决定渲染 | 同一总开关：生产 isDemoAllowed()=false 不渲染入口；demo-bar 需 user.demo（受 #1 控制） | §1：生产 /login 正文「演示」0 次 ✓；§6(i)（66-A5 增）：带伪造 Cookie 变体同断言 ✓ |
| 5 | 对账卡翻转注入（demo_fetch_logs） | ——不存在 | 64-A5 评估结论「不预埋」：卡片当前不读 fetch_logs、翻转推导未开发，预埋开关无可测对象。B2 开发同轮按设计 §6/§7 再落注入面（届时须同步补本清单与 online 断言） | 无面可测；以本行登记防遗忘。代码侧 grep `demo_fetch` 仅设计文档命中、无实现 ✓（66-A5 复核） |

## 非注入面（登记备查，不属本清单攻击面）

- `FALLBACK_*` 兜底数据（lib/data.ts）：供演示用户或 Supabase 未配置/
  查询失败时使用，不是 Cookie 注入面；生产已配置 Supabase，真实登录
  用户走 realMode 真数据，匿名用户被 middleware 导向 /login，读不到
  兜底渲染。
- 演示种子数据（线上 expense_claims 3 行「示例·」等）：真实库数据，
  与演示模式无关，清理事项见 docs/待老板_指令57.md A5。

## 核对结论（指令66 A5）

- 注入面共 4 个现存（#1–#4）+ 1 个经评估不预埋（#5），全部经同一
  总开关闸门，生产恒忽略机理逐项成立。
- audit-online 原覆盖缺口 2 处（/login 伪造 Cookie 变体、demo_targets
  单独注入），已当场补 3 项断言（49 → 52，全过，commit 见当轮验收）。
- 后续新增任何 demo-only 注入面，须同步：①在本清单登记；②在
  audit-online 补伪造注入断言；③在当轮验收文档注明。
