# 评估 · 成员邀请二期：首次登录自动对齐（指令60 A7）

> 只评估不开发。一期现状：docs/验收_指令59.md A6 节；一期前评估：
> docs/评估_成员邀请体验.md。本评估针对二期设想——**新账号首次登录
> （注册完成）时，系统按邮箱自动应用 member_invites 中 pending 的意向**
> （写角色 + 业务授权 + 标 aligned），老板不再需要回名单页点「一键对齐」。

## 1. 一期剩余摩擦（收益上限）

一期全流程：老板登记意向 → 控制台发邀 → 对方设密注册 → **老板回 /members
点「一键对齐」（二次确认）** → 对方刷新生效。二期能省掉的只有最后一步：
约 1 次页面访问 + 1 次点击，外加「老板忘了对齐、店员登录后看到默认无授权
状态来问」这一类沟通成本。以当前成员规模（老板 + 个位数店员/合伙人，
且 migration_008 尚待执行、一期真机都还没跑过），收益上限很低。

## 2. 实现路径与约束（先说清哪条路走得通）

| 路径 | 可行性 | 说明 |
|---|---|---|
| 应用层（登录后服务端顺手对齐） | **走不通** | profiles 写策略仅老板（RLS）；新账号用自己的会话改不了自己的角色。要绕开只能在服务端持 service-role 密钥——本站纪律是密钥不下发、不进 Vercel 环境变量扩面，为省一次点击引入最大权限密钥，不划算 |
| Supabase Auth Hook | 繁 | before-user-created 类钩子能拦注册但不便顺带写多表；postgres 函数钩子与触发器同复杂度，无额外收益 |
| **数据库触发器** | **唯一干净路径** | 扩展现有 handle_new_user 链路：auth.users 新建 → 按 `lower(email)` 查 member_invites pending 行 → SECURITY DEFINER 函数内写 profiles.role、user_business_access、名单标 aligned（注明自动）。原子、无新密钥、邮箱取 auth.users.email 本人值，比一期按 display_name 匹配更可靠（不依赖默认显示名） |

即：要做，只能走触发器；下面按触发器方案评估风险。

## 3. 误配风险

| 风险 | 一期（人工对齐） | 二期（自动对齐） | 缓解（若做） |
|---|---| tan---|---|
| 邮箱笔误 | 对齐弹窗二次确认邮箱+角色+授权，是最后的人工检查点；且一期匹配靠 display_name=邮箱，改过名的人不会被误配 | **检查点消失**：登记与控制台发邀若一致笔误到某个真实第三方邮箱，对方凭邮箱链接注册即刻拿到意向角色/授权，老板事后才可能发现 | 意向有效期（如 pending 超 30 天不自动应用）；对齐后名单/成员页显著留痕（已有 aligned 记录）供老板事后复核 |
| 意向过期 | 老板点击时自然会复核意向是否还成立 | 登记后隔很久才注册，岗位/授权想法已变，仍按旧意向静默生效 | 同上有效期；自动应用后给老板留可见回执（成员页 aligned 标记已有） |
| 授多/授错业务 | 弹窗明示授权清单 | 同左但无人复核 | intended_businesses 在登记时即受一期表单约束（仅 active 业务可勾） |
| 误升 owner | intended_role 约束仅 partner/staff（migration_008 已锁） | 触发器同样受该约束，**升不了 owner** | 保持约束，触发器内再断言一次 |
| 重复/并发 | 同邮箱 pending 唯一索引（一期已建） | 触发器只取那一行；注册只发生一次 | 无额外处理 |

核心判断：自动对齐的真实风险不在「陌生人乱入」（注册必须持有该邮箱的
邀请链接），而在**老板自己的笔误/过期意向失去最后一道人工复核**。

## 4. 回滚方案（若做）

- 触发器标 aligned 时同步记录 `aligned_user_id / aligned_at`（一期字段
  已有），并建议加一列标记来源（auto/manual）以便区分复核。
- 回滚动作现成：新账号的对齐前状态是确定的（默认 staff、无业务授权），
  老板在 /members 既有界面改回角色、取消授权即可；如需彻底撤销，把名单
  行删掉或改回 pending。无需为回滚新建功能。
- 停用开关现成：删掉 pending 意向即不再触发；无需配置表。

## 5. 可测性（本项的硬伤）

触发器跑在真实注册链路上，演示模式测不到、本地构建测不到；完整验证
需要真实邮箱注册一遍——与 A0'（migration_008 真机点验）、A1（晋升首跑）
卡在同一批「老板一步」事项后面。二期现在做，只能交「代码 + 未真机
验证」的半成品，与本仓「每项带验收方式」的纪律冲突。

## 6. 结论

**不做（二期暂缓）。** 理由按权重：

1. 收益太小：一期只剩一次点击，成员规模个位数，没有批量入职场景；
2. 风险结构变差：省掉的是唯一的人工复核点，笔误/过期意向将静默生效；
3. 现在无法真机验收：migration_008 尚待执行、一期真机点验未做，二期
   叠在未验的一期上，风险不可控。

**重议条件**（满足任一再排期）：一期真机跑通且实际发生过「忘了对齐」
的漏对齐；或单次要入职 ≥3 人；或成员规模明显变大。届时按 §2 触发器
方案 + §3 有效期/来源标记 + §4 回滚直接开发，预估半天内（含迁移与
真机点验清单），不另行论证。
