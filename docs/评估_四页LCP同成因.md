## 结论：同属入场动画钉点，但分两层，不能一概而论

1. 四页 LCP 元素：报销/工资/报表为首段说明文本（`P.page-desc`），
   help 为卡片内的示例截图（IMG）——都不是英雄数字，与总览 T1 前
   「被钉对象」不同，但钉点机制同源：入场动画期间内容不计有效绘制。
2. **报销、报表：钉点在容器层**。仅关 `.container` 动画即归零
   （LCP−FCP=0、LCP 228/236ms），与总览 T1 的处理方式可直接类推。
3. **工资、help：钉点不止容器层**。仅关容器无改善（工资 844/572、
   help 860/552），须容器+卡片层（`.card` 等）一并关闭才见效：
   工资归零（292/0）；help 大幅下降但未归零（416/88）——help 的
   LCP 是图片元素，卡片动画之外还叠加图片自身的加载/解码时序，
   残余以本小样不作进一步归因。
4. 因此：若只把总览的 `.no-enter`（仅免容器）原样推广到四页，
   **只能修好报销、报表两页**，工资与 help 不达预期——处理方案
   必须按层设计，不能照搬 T1 的单点改法。

## 观感评估

- 入场动画为整页/卡片 0.55–0.6s 的轻微上浮淡入，全站一致（总览
  已于 T1 单独免除容器层）。四页 LCP ~750–810ms 距 2.5s 待查线
  有 3 倍余量，**用户无可感知问题**，处理收益纯为指标与一致性。
- 卡片层动画是各页卡片的阶梯淡入，比容器层更「有存在感」；
  若处理范围扩到卡片层，观感变化大于 T1 那一笔，取舍更需裁定。

## 选项（等裁定，本轮不执行）

- **甲（若处理，须按层设计）**：全站统一处理入场动画——容器层 +
  卡片层一并免除或改为不钉绘制的呈现。预期（按本小样）：报销
  ~230–240ms、报表 ~240–270ms、工资 ~290ms、help ~420ms 量级。
  代价：整站失去页面与卡片入场感，观感变化最大。
- **乙**：只推广 `.no-enter`（仅容器层）到四页——实测只能修
  报销/报表，工资/help 无效，**不推荐**（初版曾误荐此类形态，
  随本次更正撤回）。
- **丙**：维持现状——指标在待查线内 3 倍余量，观感全站一致（除
  总览容器层），零改动风险；待整站改版时一并决定。

本评估倾向：**丙可接受；若要处理则按甲的按层形态**，请督工裁定。
