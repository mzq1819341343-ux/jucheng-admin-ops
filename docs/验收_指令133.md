## A2 中间件 getClaims 评估（结论：前置满足，已落地快路径 + 回落兜底）

证据（本轮实测，非推断）：
1. **JWKS 在册非对称公钥**：`GET https://<项目>.supabase.co/auth/v1/.well-known/jwks.json` 返回 1 把 EC 公钥（kty=EC、crv=P-256、alg=ES256、含 kid、use=sig）——项目 JWT 已切非对称签名，前置条件成立。
2. **库实现核读**（auth-js 2.118.0 `getClaims` 源码）：无参时先走会话读取（ssr 客户端在此阶段完成过期刷新并回写 Cookie）；令牌 alg 为 HS* 或无 kid 时内部自动回落 `getUser()` 权威校验；ES256 令牌走 JWKS 本地验签（签名 + exp），JWKS 按 kid 缓存（暖实例零网络）。
3. 落地（`6ea4f4c`）：proxy 改为先 `getClaims()`，取不到 claims（无会话 / 对称旧令牌 / JWKS 不可达）才回落 `getUser()`；两条跳转分支（未登录 → /login、已登录访问 /login → /）与原行为逐路一致。
4. 已知取舍（如实登记）：已删除/封禁账号持未过期令牌时，快路径信任至令牌过期为止（≤ 令牌寿命）；页面数据层 `getCurrentUser` 仍逐请求走 getUser + profiles、RLS 不受影响，风险面仅为中间件页面门禁一层。
5. 收益口径：暖实例每请求省 1 次 Auth 服务端往返（hkg1 ↔ 新加坡约 40ms 量级，且不再占用 Auth 服务端）；冷实例需多 1 次 JWKS 拉取（可缓存、与原 getUser 往返大体抵消）。**真实登录态时延数字归督工 Mac/真机复核，本轮不编数。**
