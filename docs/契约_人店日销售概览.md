# 契约 · 人店日销售概览（表 daily_person_store_sales）

总览的走势和排名读 `public.daily_person_store_sales`。这张表是人 × 店 × 日的实绩，不是月目标。月目标在 `monthly_sales_targets`（`supabase/migration_018_monthly_sales_targets.sql`），本契约不读、不写那张表。

本仓没有 Next.js route。下面两个形状给 web 仓的服务端 Route Handler 照着实现。Python CLI 是同一形状的只读参考，也留给本机 / ops。

不新增 migration。表已经在线上，本仓不代执行、不重放建表 SQL。不改工资算数，不改 `scripts/payroll/`，不改 `scripts/apply_realtime_payroll_draft.py`，不改 `docs/fetch-pipeline/pipeline_config.json` 的 `UPLOAD` / `APPLY`（保持 false）。

## 不做的事

- 不登录加盟后台，不跑抓数，不写 `salary_fetch_runs`。
- 不写 `salary_realtime_draft` / `salary_detail_import` / `salary_monthly`，不算薪。
- 种子不读 `ALLOW_APPLY_REALTIME_DRAFT`、`ALLOW_EMPLOYEE_DRAFT_WRITE`，也不靠 `UPLOAD` / `APPLY` 放行。
- 不在本变更里对生产库执行 upsert。2026-11 的 56 行已经在库侧写过，见文末。

## 表

`public.daily_person_store_sales`。唯一键 `(day, person_name, store_name)`。

| 列 | 含义 |
|---|---|
| `day` | 日期 `YYYY-MM-DD` |
| `month` | `YYYY-MM`。种子从 `day` 推导，不单独采信一个对不上的月份 |
| `person_name` | 人名，精确匹配，不做姓名合并 |
| `store_name` | 店名，精确匹配 |
| `recycle_store_amount` | 门店回收，`numeric(14,2)` |
| `recycle_online_amount` | 网单不含券，`numeric(14,2)` |
| `accessories_sales` | 配件销售额，`numeric(14,2)` |
| `n_old_machine` | 旧机件数，可空 |
| `n_accessories` | 配件件数，可空 |
| `updated_at` | 最近写入时间 |

响应不带 `id`。金额在 JSON 里是两位小数的十进制文本（`"2925.72"`），避免 JSON number 丢分。前端画图时再转成数字。没有行的日期不补 0；走势要连续日期时由页面自己补。

## 鉴权

与其它工资只读相同。本契约不新开角色、不改登录、不改 RLS。

- web：Route Handler 在服务端。先确认 owner 会话（与工资只读同一道门），再用服务端 service role 读这张表。service role 绕过 RLS，所以会话检查必须在查询之前。浏览器、店员会话、`NEXT_PUBLIC_` 变量都不得持有 service role。
- 本仓 CLI：`SUPABASE_URL`（或 `NEXT_PUBLIC_SUPABASE_URL`）加 `SUPABASE_SERVICE_ROLE_KEY`（或 `SUPABASE_SERVICE_ROLE`）。只从环境读取，不进命令行、不进仓库。

合伙人、店员要不要看总览，沿用页面上已经有的门。本契约不另加一条。

## 1. 按日合计

web：`GET /api/ops/daily-person-store-sales/daily?month=YYYY-MM`

CLI：

```bash
python3 scripts/daily_person_store_sales.py daily --month 2026-11
```

`month` 必填，形如 `2026-11`。没有其它筛选。服务端取出该月全部人 × 店 × 日行，再按 `day` 把三个金额相加。

成功 HTTP 200，正文是数组。没有行时是 `[]`。

```json
[
  {
    "day": "2026-11-01",
    "recycle_store_amount": "150.50",
    "recycle_online_amount": "20.00",
    "accessories_sales": "1.25"
  }
]
```

按 `day` 升序。只含这四个字段。排序用字符串码点，不按中文拼音。页面若要拼音序，在展示层另排。

web 实现要点：用 service role `select` 下列，`eq('month', month)`，按 `day, person_name, store_name` 排序后自己加总。PostgREST 默认分页。请求带 `Prefer: count=exact`，按 `Content-Range` 的总数翻页；短页却还没凑满总数时不要把残页当成整月。列：

`day, month, person_name, store_name, recycle_store_amount, recycle_online_amount, accessories_sales, n_old_machine, n_accessories, updated_at`

月份非法时 CLI 退出码 1；web 回 400。未登录或不是 owner 时 web 回 401/403，不要带着 service role 去查。

## 2. 人 × 店 × 日明细

web：`GET /api/ops/daily-person-store-sales?month=YYYY-MM`

可选 query：`day=YYYY-MM-DD`、`person_name`、`store_name`。省略即该月全部。`day` 必须落在 `month` 里。姓名和店名是精确匹配，区分空格。

CLI：

```bash
python3 scripts/daily_person_store_sales.py detail --month 2026-11
python3 scripts/daily_person_store_sales.py detail \
  --month 2026-11 --day 2026-11-01 --person-name 示例甲 --store-name 示例店
```

成功 HTTP 200，正文是数组，按 `day`、`person_name`、`store_name` 的字符串码点升序。没有行时是 `[]`。

```json
[
  {
    "day": "2026-11-01",
    "month": "2026-11",
    "person_name": "示例甲",
    "store_name": "示例店",
    "recycle_store_amount": "100.50",
    "recycle_online_amount": "20.00",
    "accessories_sales": "1.25",
    "n_old_machine": 2,
    "n_accessories": 1,
    "updated_at": "2026-11-08T18:00:00+08:00"
  }
]
```

件数是整数或 `null`。`updated_at` 沿用库里的时间戳文本，没有则 `null`。

## 种子（ops，默认不写）

给补数用。web 不要做这条上传口。生产上的 2026-11 已经有数，验收不要再 `--apply`。

CSV 表头要有：`day,person_name,store_name,recycle_store_amount,recycle_online_amount,accessories_sales`。`n_old_machine`、`n_accessories` 可空；空单元格写成 `null`，`0` 仍是 0。`month` 可省略；写了就必须等于该行 `day` 的 `YYYY-MM`。`id`、`updated_at` 即使出现也不采用，`updated_at` 用本次运行的上海时间。金额最多两位小数，千分位逗号会去掉。同一文件里冲突键重复则整文件拒绝，一行都不写。

只 upsert 文件里的键，不删除文件里没有的行。

```bash
python3 scripts/daily_person_store_sales.py seed \
  --csv scripts/fixtures/daily_person_store_sales_sample.csv \
  --month 2026-11
```

上面是 dry-run：标准输出 JSON，`wrote` 为 false，并带上将写入的行。不连库。

真正写库要两道一起开，缺一则仍然不写：

```bash
ALLOW_DAILY_SALES_SEED=true \
SUPABASE_URL=https://<project>.supabase.co \
SUPABASE_SERVICE_ROLE_KEY=<service-role-key> \
python3 scripts/daily_person_store_sales.py seed \
  --csv <本机 CSV> --month 2026-11 --apply
```

PostgREST：`POST /rest/v1/daily_person_store_sales?on_conflict=day,person_name,store_name`，`Prefer: resolution=merge-duplicates,return=minimal`。`month` 由 `day` 写入。

| 条件 | 结果 |
|---|---|
| 没设 `ALLOW_DAILY_SALES_SEED=true`，或没带 `--apply` | dry-run，不连库 |
| 只打开工资灌数闸或员工草案闸 | 不放行 |
| `ALLOW_DAILY_SALES_SEED=true` 与 `--apply` 同时成立 | 才 upsert |
| 闸开了但没有库凭据 | 退出码 1，不写 |

`ALLOW_DAILY_SALES_SEED` 去掉首尾空格后大小写不敏感，只认 `true`。`1` / `yes` 不放行。

给 ops 在同进程里复用的函数（web 不要 import 这个文件）：

- `daily_totals(month, *, env=None, transport=None, row_source=None)`
- `person_store_days(month, *, day=None, person_name=None, store_name=None, env=None, transport=None, row_source=None)`
- `seed_csv(path, *, month=None, env=None, apply=False, writer=None, transport=None, now=None)`

`row_source(spec)` 与 `writer(rows)` 只给冒烟替换客户端。缺省才走 PostgREST。
