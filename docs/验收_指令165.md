## 一、本轮代码变更（产品/性能实质，两处）

### 1. `proxy.ts` —— 无鉴权 Cookie 快路径
- 请求不带任一 Supabase 鉴权 Cookie（`sb-<ref>-auth-token`，含分片 `.0/.1` 与 `-code-verifier` 变体）时，跳过建 SSR 客户端与 `getClaims()`/`getUser()` 两次会话读取，直接按 `authed=false` 走原重定向逻辑。
- 等价性依据（读 `@supabase/auth-js` 2.118 已装源码核对）：无会话时 `getClaims` 在 `getSession` 无会话处直接返回空（不拉 JWKS、不发网络）；`getUser` 以 `AuthSessionMissingError` 作**返回值**本地返回（不发网络、不写 Cookie）。故原流程对这类请求结论恒为未登录、响应不带 Set-Cookie，快路径逐路等价。
- 带任一鉴权 Cookie 的请求（含过期会话待刷新、已登录用户访问 /login 跳首页）走原全路径，代码一字未动。
- 本地真实模式构建（带 Supabase URL、无演示）逐路 curl 验证八路全等：无 Cookie `/`→307 /login、`/login`→200 且无 Set-Cookie、`/auth/set-password`→200、`/help` `/salary`→307；垃圾 sb Cookie `/login`→200、 `/`→307（全路径结论与快路径一致）；生产门控下 demo Cookie 访问 `/`→307（演示被忽略，与设计一致）。

### 2. `app/login/page.tsx` —— supabase-js 懒加载 + 鉴权域名预连接
- 原静态 `import { createClient } from "@/lib/supabase/client"` 把 supabase-js（约 259KB 未压缩）拖进登录页首屏，而它只在提交时用一次。改为提交时经 `lib/supabase/config.ts` 的 `createBrowserSupabase()` 懒加载（与 132-A4 全站口径一致，客户端构造方式不变）；`isSupabaseConfigured` 改从零依赖的 config 直引（client.ts 本就是转发它）。
- 渲染期对鉴权域名 `preconnect`（crossOrigin=anonymous），抵消点击登录时懒加载现建 TLS 的一次往返。
- `/auth/set-password` 页**未动**：其 createClient 在挂载 useEffect 即用于承接邮件链接会话，不属 P0 登录路径，行为敏感，不在本轮冒险面内。

## 二、/login 请求路径耗时嫌疑排序（摸排结论）

| # | 环节 | 判断 |
|---|---|---|
| 1 | 中国（新疆）→ 入口 PoP（Mac 路由为 sin1）的网络往返：TCP 1 RTT + TLS 1.3 1 RTT + 请求/响应 | **主项**。curl 的 TTFB 含建连，约 410ms 里大半在此；代码不可改，只能靠边缘就近接入 |
| 2 | 中间件（proxy）在静态页出缓存前先行执行：建 SSR 客户端 + `getSession` 两遍（getClaims 后再 getUser 回落） | 无会话时纯本地开销（毫秒级、冷实例更高），本轮已以快路径整段削掉 |
| 3 | 带**过期**会话 Cookie 的真实浏览器回访 /login：getSession 会触发刷新令牌的网络 POST（往新加坡 Supabase） | 仍在（语义必需：已登录跳首页靠它）；快路径不覆盖、不假装已解 |
| 4 | 登录页首屏 JS 解析执行（supabase chunk 67KB 编码后） | 不影响 HTML 的 TTFB，影响表单可交互；本轮懒加载已削（见三） |

/login 本身是构建期静态预渲染页（构建路由表 `○ /login`），HTML 由边缘缓存出，不跑函数——这决定了下一节的区域结论。

### 2. 区域结论（sin1 的原因与可接受性）
- /login 为静态预渲染页，响应由 Vercel 边缘缓存给出；x-vercel-id **第一段是请求进入 Vercel 网络的入口 PoP**，由客户端 ISP 的 anycast/BGP 路由决定（老板 Mac 的路由落在新加坡 sin1），**不是函数区域**。`vercel.json regions:["hkg1"]` + 根 layout `preferredRegion="hkg1"` 钉的是**函数执行地**，作用于 SSR 路由（如总览 `/` 为 ƒ 动态）与 Server Action；把 /login 改成动态以「迁就」hkg1 只会平白加一次函数往返，得不偿失。
- **可接受性结论：可接受。** sin1 为亚太一线 PoP，与 hkg1 同量级；配置层无任何美国区域，**iad1 回退在配置上不存在**。本轮 VM 侧采样出现的 iad1/pdx1/cle1 是**本台 VM 自身出口走美国**所致（见下），与老板 Mac 的 sin1 路由是两条网络路径，不可混读，更不是生产回退 iad1。
- 登录态 SSR 响应的 x-vercel-id 第二段（函数区段）应为 hkg1，待督工登录后复核——这是区域项唯一未落锤处。
