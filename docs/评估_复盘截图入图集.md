# 评估：复盘截图入 help-shots 图集（指令62 A4，只评估）

> 问题：给 /help「目标达成复盘」节配一张报表页复盘节截图（图集八图 → 九图），
> 值不值得做？本评估先立达标线、再用试截实测数据判定，**结论：不达标，
> 本轮不做，保留八图**。

## 达标线（先立后测）

| # | 维度 | 达标线 |
|---|---|---|
| 1 | 体积 | 量化后 ≤ 同类区块图量级（约 ≤100KB），可纳入 62-A2 体积守线 |
| 2 | 信息量 | 截图须呈现四状态分支中 ≥3 类的有效行，而非整表空态 |
| 3 | 版面 | 构图与既有图集一致（紧凑区块或首屏），不出现需大幅缩放才看清的长图 |
| 4 | 维护 | 新增维护点可控（截图管线/图注/守线/断言同步面已知且一次改齐） |

## 试截实测（2026-10-27，本地演示构建，老板会话，元素截图口径同既有区块图）

复盘节区块尺寸 **1216 × 1428 CSS px**（27 行全表），两种内容形态各试截一张：

| 形态 | 原始体积 | 256 色量化后 | 状态分布（27 行） |
|---|---|---|---|
| 默认态（无目标注入） | 169,227B | 64,387B | 未设定 ×27 |
| 注入示例目标（同 audit 三分支注入） | 173,978B | 66,215B | 未设定 ×24、已达成 ×1、未达成 ×1、待核算 ×1 |

## 逐项判定

1. **体积：达标。** 量化后约 66KB，与 compare.png（87,218B）同量级，守线
   （基线 ×1.3 ≈ 86KB）可纳管。体积不是本次拦路项。
2. **信息量：不达标。** 默认态整表 27 行全「未设定」；即便注入示例目标，
   仍有 24/27 行为未设定，真正传达四状态的有效行只有 3 行。截图给读者的
   第一印象是「一张空表」，与复盘节文字（在哪看/三口径/四状态词）的教学
   目的相悖；且注入态是人为构造的目标值，与任何用户实际所见都不一致，
   放进手册易误导（以为示例数字是系统预置）。
3. **版面：不达标。** 1428px 高的长图放进 /help：按版心宽度缩放后行高
   只剩约 20px、字不可读；原尺寸展示则独占一整屏以上。既有八图均为紧凑
   区块或首屏构图，长表图与图集风格不一致。
4. **维护：中性偏负。** 做九图需同步改 ≥4 处：capture-help-shots（截图步
   + QUANTIZE_FILES + 图注改写计数「八处」）、audit-online（文件清单 +
   SHOT_SIZE_CAPS + 图注 8→9 处断言）、/help 图注、运维清单；且复盘列/口径
   每变一次都要重截整张长图。在 2、3 不达标的前提下，这份维护负担买不到
   对应收益。

## 结论与重议条件

**不做九图，保留八图。** /help 复盘节维持纯文字说明（指令61 A6 已补齐：
在哪看/三口径/四状态词/双导出权限），不配图。

重议触发（满足其一再评）：
- 复盘表改版为「只列已设定/有实际月份 + 其余折叠」等紧凑形态，区块高度
  降到首屏量级；
- 实际使用中多数月份已设定目标，已设定/已达成行占多数，长表本身有信息量；
- 改走**局部图**折中：只截含三分支的最近两月行 + 双导出按钮区（高度约
  300–400px），信息密度与版面可同时达标——届时按新图单独评估，不沿用
  本结论直接开工。
