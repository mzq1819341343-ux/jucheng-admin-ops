# 运维 · 回归清单（指令57 A8 固化）

> 每轮 UI/权限改动后跑一遍。脚本在 `scripts/regression/`，基于 Playwright
> （playwright-core，无头 chromium），断言标准写在本文件与各脚本头注释里。
> 本地部分跑「生产构建 + 演示会话」，线上部分只做未登录侧断言；不登录真实
> 账号、不索取密码、不动 Supabase 控制台。

## 前置

```bash
# 1) 依赖（playwright-core 已在 devDependencies）
npm install
# 2) 本机需有 chromium headless shell：~/.cache/ms-playwright 下任一版本，
#    或用环境变量 CHROMIUM_PATH 指定可执行文件
# 3) 本地被测服务：演示开启的生产构建（仅本地，生产 Vercel 构建不带此变量）
NEXT_PUBLIC_ALLOW_DEMO=1 npm run build
PORT=3100 npm run start        # REG_BASE 默认 http://localhost:3100
```

## 命令

```bash
npm run regression            # 全跑：布局审计 + 员工 absent + 锚点哨兵 + 状态页一致性 + 线上未登录侧
npm run regression:390        # 只跑布局审计（scripts/regression/audit-390.mjs）
npm run regression:staff      # 只跑员工视角 absent 审计（audit-staff.mjs）
npm run regression:anchors    # 只跑演示数据漂移哨兵（audit-anchors.mjs，指令58 A5）
npm run regression:online     # 只跑线上未登录侧（audit-online.mjs，REG_ONLINE 可改目标）
node scripts/regression/capture-help-shots.mjs   # 刷新 /help 八张截图（A7）；跑完自动把 /help 八处图注「截图刷新」日期对齐为当日（指令58 A2）
```

退出码：0 = 全过；1 = 有 FAIL；2 = 本地服务不可达（环境问题，不是页面失败）。

## 判定标准

### audit-390（三角色演示会话 × 390×844 + 1440×1000 双视口；指令59 A3 扩围，老板/合伙人六页：总览/报销/工资/成本/对比/help，店员五页：成本页直进被拦回不在布局页集，拦截由 audit-staff 断言）
- 每页 HTTP 200；
- 页面级横向溢出 = 0（documentElement.scrollWidth ≤ 视口宽）；
- 文本撞线 = 0（叶子文本 scrollWidth > clientWidth+2 且 overflow 可见、非 nowrap）；
- 超宽元素必须全部归属 `.table-wrap` 容器（容器内滚动为设计内）；容器外越界即 FAIL，
  输出会给出 tag/class/文本片段定位。
- <30px 触控热区只作 info 记录（品牌字标等既有例外），不判 FAIL，但新增项要在验收文档里说明。

### audit-staff（店员演示会话，桌面视口）
- 文本轨：渲染后可见文本（innerText）不得出现敏感金额与口径串
  （净利金额 −6,313 / 6,312.51 / −11.9%、单店净利额、工资实发合计 244,757、他人姓名等，逐页清单在脚本内）；
- 标签轨：敏感词不得作为数据标签渲染（叶子元素完整文本等于标签才算命中）；
- 禁用串轨（指令58 A3 督工裁定）：店员可达业务页（总览/仪表盘/报表/对比/工资/报销/
  成员/状态）一律不得出现「无权限」「仅老板可见」「仅老板 / 合伙人可见」
  「敏感列已按权限隐藏」「已按权限隐藏」——无权限内容整行/整节不渲染，
  报表/对比页首的权限说明行已按裁定撤下（不再有「定性保留」）；
  /help 为手册文档（权限矩阵与说明是文档内容本身），不在此轨范围；
- 成员页：店员整段不渲染——无「成员列表与业务授权」标题、无邮箱、无授权 checkbox，
  只剩角色说明表；
- 状态页：工资明细对账行整行不渲染、抓取/导入日志整节不渲染、登录恢复操作指引不渲染；
- 直进拦截：/business/aihuishou/costs、/breakdown 店员直进被拦回（URL 带 denied=），目标页标志串不渲染；
- 合伙人轨（指令58 A6）：同一脚本第二会话——合伙人可见经营汇总（总览净利、
  报表敏感列与目标复盘、状态页抓取日志），不可见明细与个人工资（工资页只有
  门店汇总、报销只有按月汇总、成员页无邮箱无控件、状态页工资对账行不渲染）。

### audit-anchors（老板演示会话，桌面视口；指令58 A5）
- 锁定锚点逐页在位：1–9 月 3,958 单 / 分润 416,661.32；2026-09 分润 53,220.60、
  公司口径净利 −6,312.51（总览英雄取整 −6,313）；工资 244,757.00；2026-09
  门店成本 11,183.37；双利润率 分润口径 −11.9% / 营收口径恒「—」；
  对比页 9 月分店锚点（友谊 −5,503.06 / 万达 −809.45 等）。
- 任一 FAIL = 演示兜底数据或核算口径漂移：先查 lib/data.ts 兜底与 lib/operating.ts
  口径改动，确认是有意变更才同步改锚点并在验收文档记录，禁止为过检随手改锚点。

### audit-online（生产 https://jcxj.cc，未登录）
- /login 200 且「演示」出现 0 次；
- 六条登录后路径未登录访问全部 307 → /login；
- 伪造 demo Cookie（demo_role=owner）仍 307；
- /help-shots 八张图全部 200 且 content-type=image/png；
- /help 图注日期（指令58 A2）：生产 /help 未登录读不到正文，图注随同一次构建发布，
  故对本地演示构建的同一 /help 断言八处「截图刷新：YYYY-MM-DD」存在、格式正确、
  八处同一日；本地服务不可达时跳过并 info 提示（全跑时必跑）。

## 失败如何定位

- **390 FAIL（容器外超宽）**：按输出的 tag/class/文本在对应页面找元素；常见原因：新表格没包
  `.table-wrap`、长串英文/数字没给断行、flex 子项缺 min-width:0。修后单跑 `npm run regression:390` 复验。
- **staff FAIL（文本轨命中）**：多半是新加的卡片/脚注没按角色设防——对照同页既有写法用
  `sensitive` / 角色判断整块不渲染（禁止灰显占位），修后单跑 `npm run regression:staff`。
- **staff FAIL（标签轨命中）**：表头/卡标题对店员渲染了敏感列，检查该表是否按角色拼列。
- **online FAIL（演示出现/307 失效）**：先查生产构建是否误带 NEXT_PUBLIC_ALLOW_DEMO=1
  （Vercel 环境变量），再查 middleware 与 lib/demo.ts 的 isDemoAllowed 判定；此项 FAIL 按致命处理。
- **online FAIL（图片非 200）**：多为部署未完成或图片被改名；先等部署完成复跑，仍失败查 public/help-shots 与 /help 引用是否同名。
- **退出码 2**：本地服务没起或端口不对，按「前置」第 3 步启动后重跑，不要把环境问题记成页面缺陷。

## CI（指令58 A1）

- workflow 设计为双 job（build-online：生产构建 + audit-online；demo-regression：
  装 chromium headless shell + 演示构建自起服务 + run-all 全套），文件在本地
  分支 `ci-workflow`（commit efeafb9），**尚未进 main**：当前 gh 令牌缺
  `workflow` scope，推送 workflow 文件被 GitHub 拒绝。解法见 docs/验收_指令58.md
  第 6 节（补 scope 后 `git push origin ci-workflow:main`）。
- 在 CI 启用前，回归仍以本地 `npm run regression` 为准（本机全套约 1 分钟）。
