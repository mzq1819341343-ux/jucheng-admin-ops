# 运维 · 回归清单（指令57 A8 固化）

> 每轮 UI/权限改动后跑一遍。脚本在 `scripts/regression/`，基于 Playwright
> （playwright-core，无头 chromium），断言标准写在本文件与各脚本头注释里。
> 本地部分跑「生产构建 + 演示会话」，线上部分只做未登录侧断言；不登录真实
> 账号、不索取密码、不动 Supabase 控制台。

## 前置

```bash
# 1) 依赖（playwright-core 已在 devDependencies）
npm install
# 2) 本机需有 chromium headless shell：~/.cache/ms-playwright 下任一版本，
#    或用环境变量 CHROMIUM_PATH 指定可执行文件
# 3) 本地被测服务：演示开启的生产构建（仅本地，生产 Vercel 构建不带此变量）
NEXT_PUBLIC_ALLOW_DEMO=1 npm run build
PORT=3100 npm run start        # REG_BASE 默认 http://localhost:3100
```

## 例行：截图—手册对齐（指令60 A5 固化，每轮首项）

每轮开发开始前先跑一遍，保证 /help 截图与手册文案不与实现漂移：

1. `npm run shots` 刷新八图（本地演示服务需已启动；两张手机长图自动量化，
   图注日期自动对齐当日）；
2. `npm run regression:online` 确认图注断言（八处日期存在/同日/与当日一致）与八图 200；
3. /help 逐节核对：沿最近一轮验收文档的核对表逐节扫（权限矩阵行数与口径、
   三角色动线步数与页面实名、公式与合同数字、导出按钮文案），过时项当场修
   （独立 commit），无过时项也要在当轮验收文档留下执行记录；
4. 截图内容有实质变化（非像素噪声）时，在当轮验收文档写明变化点；
5. `npm run salary:verify` 顺带跑一次（指令64 A4 固化）：工资晋升 dry-run
   的虚构样本期望校验（sample-data / sample-boundary / sample-empty 三份，
   关键行逐行对位），防样本/口径漂移无人察觉；结果记入当轮验收文档。
   本项只校验虚构样本与演算口径，零写入、不连库、不含真实姓名金额。

## 命令

```bash
npm run regression            # 全跑：布局审计 + 员工 absent + 锚点哨兵 + 状态页一致性 + 复盘导出一致性 + 线上未登录侧
npm run regression:390        # 只跑布局审计（scripts/regression/audit-390.mjs）
npm run regression:staff      # 只跑员工视角 absent 审计（audit-staff.mjs）
npm run regression:anchors    # 只跑演示数据漂移哨兵（audit-anchors.mjs，指令58 A5）
npm run regression:status     # 只跑 /status 与 10 月运行单一致性（audit-status-consistency.mjs，指令59 A4）
npm run regression:review     # 只跑复盘导出一致性（audit-review-export.mjs，指令61 A4）
npm run regression:online     # 只跑线上未登录侧（audit-online.mjs，REG_ONLINE 可改目标）
node scripts/regression/capture-help-shots.mjs   # 刷新 /help 八张截图（A7）；跑完自动把 /help 八处图注「截图刷新」日期对齐为当日（指令58 A2）
```

退出码：0 = 全过；1 = 有 FAIL；2 = 本地服务不可达（环境问题，不是页面失败）。

## 判定标准

### audit-390（三角色演示会话 × 390×844 + 1440×1000 双视口；指令59 A3 扩围，老板/合伙人六页：总览/报销/工资/成本/对比/help，店员五页：成本页直进被拦回不在布局页集，拦截由 audit-staff 断言）
- 每页 HTTP 200；
- 页面级横向溢出 = 0（documentElement.scrollWidth ≤ 视口宽）；

  输出会给出 tag/class/文本片段定位。

  Asia/Shanghai 动态推导/含数据月 2026-09/保存后本月分润行/无数据月实际=待核算/调整

## 失败如何定位

- **390 FAIL（容器外超宽）**：按输出的 tag/class/文本在对应页面找元素；常见原因：新表格没包
  `.table-wrap`、长串英文/数字没给断行、flex 子项缺 min-width:0。修后单跑 `npm run regression:390` 复验。
- **staff FAIL（文本轨命中）**：多半是新加的卡片/脚注没按角色设防——对照同页既有写法用
  `sensitive` / 角色判断整块不渲染（禁止灰显占位），修后单跑 `npm run regression:staff`。
- **staff FAIL（标签轨命中）**：表头/卡标题对店员渲染了敏感列，检查该表是否按角色拼列。
- **online FAIL（演示出现/307 失效）**：先查生产构建是否误带 NEXT_PUBLIC_ALLOW_DEMO=1
  （Vercel 环境变量），再查 proxy.ts 与 lib/demo.ts 的 isDemoAllowed 判定；此项 FAIL 按致命处理。
- **online FAIL（图片非 200）**：多为部署未完成或图片被改名；先等部署完成复跑，仍失败查 public/help-shots 与 /help 引用是否同名。
- **退出码 2**：本地服务没起或端口不对，按「前置」第 3 步启动后重跑，不要把环境问题记成页面缺陷。
