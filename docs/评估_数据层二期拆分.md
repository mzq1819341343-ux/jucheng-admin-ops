# 评估 · 数据层二期拆分（指令69 A7，只评估未开发）

> 对象：`lib/data-finance.ts`（674 行，68-P0-2 拆分后的全仓最大文件）。
> 评估按 工资/成本/报销 三域再拆的收益与导入面影响，**本轮不预拆**，
> 等督工裁定。

## 现状：文件内域分布（按导出位置实查）

| 域 | 内容 | 大致行段 |
|---|---|---|
| 工资 | SalaryRule / SalaryMonthlyRow / SalaryStoreAgg / SalaryDetailImportRow 类型；getSalaryRules、getPublicSalaryRule、FALLBACK_SALARY_RULE、getMySalary、getAllSalaryMonthly、getSalaryDetailImport、salaryDetailByMonth、getSalaryStoreAgg | 19–51、129–287 |
| 目标（三域之外） | SiteTarget 类型 + getSiteTargets（含 demo_targets 注入分支） | 66–127 |
| 成本 | StoreCost 类型、getStoreCosts、seedCost 与月份常量、FALLBACK_STORE_COSTS、describeMonthCosts；合同 StoreContract、FALLBACK_CONTRACTS、getStoreContracts、storeCostsTotalForMonth | 52、289–356、560–643 |
| 报销 | ExpenseClaim / ExpenseMonthlyAgg、FALLBACK_EXPENSE_CLAIMS、aggregateExpenseClaims、getExpenseClaims、getExpenseMonthlyAgg、getExpenseOperatingInput | 362–553 |
| 跨域杂项 | getConfigFreshness（读 salary_rules + store_costs 两表，给状态页） | 645–674 |

域间耦合实查：各域函数只依赖 `data-core` 的 `realMode/CurrentUser`、
`supabase/server` 与共享小模块（stores/expenses/format）；域与域之间
**无函数级互相调用**（getExpenseOperatingInput 只用本域汇总；
getConfigFreshness 直查两表、不经域函数）。`lib/operating.ts`、
`lib/targets.ts` 均不 import 数据层（以参数收行），无连带。

## 若拆：目标形态

- `data-salary.ts` ≈270 行（工资全域）；
- `data-costs.ts` ≈230 行（成本 + 合同台账）；
- `data-expenses.ts` ≈200 行（报销全域）；
- 目标域与 getConfigFreshness 的归属二选一：(i) 独立 `data-targets.ts`
  ≈90 行、新鲜度留在瘦身后的 data-finance（名实转为「杂项」）；
  (ii) 目标并入 data-core 侧、新鲜度随成本域——两案均可，形态等裁定。
- 类型转发归属随域走：StoreScope/CostType 随成本、ExpenseScope/Status
  随报销（现挂在 data-finance 头部转发）。

## 导入面影响：消费方零改动

全仓消费方（app/*、components/* 共二十余处）一律经 barrel
`@/lib/data` 导入，无一直接引用 data-finance；barrel 现为
`export * from "./data-core"` + `export * from "./data-finance"` 两行，
拆分只需把后者换成三（四）行转发。**这是本拆分最大的安全垫**：
导出名集合不变，页面与组件一行不改。

## 收益与风险

收益：最大文件 674 → ≈270 回到全仓中位；三域后续各自演进（工资
晋升落地、成本电费、报销迭代）时同文件冲突面显著缩小；按域定位
更快，文件头溯源注释可按域收紧。

风险与成本：①纯搬运 diff 大（约 674 行移动），review 集中一轮；
②FALLBACK_SALARY_RULE / FALLBACK_STORE_COSTS / FALLBACK_EXPENSE_CLAIMS
是演示口径与 audit-anchors 的锚点数据源，搬运必须逐字不变——以
build + 全量回归（anchors 40 项为核心闸）可完全兜住；③块头注释的
指令溯源要随块迁移，不能丢；④拆后 data-finance 若只剩杂项，存在
名实不符的小尾巴（见上二选一）。

## 结论（等裁定）

**可拆、但不迫切**：674 行未破 800 行线、域间已天然低耦合，收益
以可维护性为主、无功能收益。若裁定执行，建议 move-only 独立一笔
（零逻辑改动）、在无功能改动的安静轮落地并以全量回归为闸；不建议
与功能轮混跑。本轮只评估，未预拆、未动代码。
