## 演练澄清的一处推导口径（设计文档已同步修订）

现行 `getFetchRefreshMarker` 的 lastSuccessAt 是**全源**口径
（`logs.find(status==='success')`，含 cockpit 手动导入行）；卡片状态机
（设计 §2）只看 `source='aihuishou_auto_fetch'`。两者在 B1 写入
auto_fetch success 后数值恰合，但推导不同：开发时卡片须**先按 source
过滤再取最新**，不得直接拿 marker 的 lastSuccessAt 当卡片触发（否则
未来一次 cockpit 手动导入也会误翻卡）。设计 §6「与 marker 同一推导」
已修订为「推导方法一致（created_at 倒序取最新），但先按 source 过滤」。
另核对：`getFetchLogs` DB 侧已按 created_at 倒序 limit 20，「最新」
口径成立；兜底数组顺序即倒序约定，开发时勿打乱。
