## 三、口径定案【已拍板】（2026-10-29）

老板已拍板。脚本常量锁定，不再标「假设·待老板确认」。`salary_rules.commission_rules` 不补「线上定义」列、本仓不跑 SQL；定义写在本文与 `scripts/payroll/realtime_payroll.py` 文件头。本仓无 web 镜像常量（驾驶舱人效卡若仍写「来源=官网」，在前端仓，本变更不改页面）。

- **H1 线上（已拍板）**：除门店业绩外一律算线上，×1%。
  `commission_rules` 只有 `online_order_pct: 1`，没有「线上 / 门店业绩」的列名。orders37 里和「门店」相关的列不是同一刀，以映射表既有用/不用为准：
  - **采用** `来源类型`（191 全量 distinct：BD 205 / 门店 175 / 官网 78）。门店业绩 = `来源类型 == "门店"`；线上 = `来源类型 != "门店"`（BD、官网，以及除此之外的任何非门店来源，含空来源）。这些订单的「订单金额（不含券）」合计 × 1%。常量 `ONLINE_MODE = "source_not_门店"`。旧值 `source_官网` 不再保留为可切换分支，写回去脚本直接报错。
  - **不采用** `是否门店订单` / `交易方式=门店订单`（同口径 172 单，本表标不用/对照）。交易方式「O2O订单」（90 单，不含券合计 162,560.00 → 旧对照池 1,625.60）也不是定案口径。
  - **废止** 旧假设「仅来源类型=官网」（78 单，不含券合计 115,585.00 → 提成池 1,155.85）。该池只作旧口径历史锚点。
  - 非门店来源的不含券金额同时进入线上 1% 与门店阶梯基数。两笔提成按各自已拍板规则各算一笔，不是二选一。H2 的基数范围没有改成「只留来源类型=门店」。

- **H2 门店（已拍板；计算与常量本来就是这样，本轮只去掉「假设」）**：业绩基数 = `订单金额（不含券）`（`STORE_BASE_FIELD`，全量订单按店合计，不按来源类型剔除）。阶梯取最高达成档：≥60,000 → 4%；≥30,000 → 3%；未达 30,000 → 0%（`STORE_TIERS`）。个人提成 = Σ（个人在该店的基数 × 该店档位率）。
  数据事实（已拍板后仍然成立，不是待选项）：该列对「来源类型=门店」的 175 单里只有 3 单非空，门店阶梯基数主要落在 BD/官网等非门店来源的不含券金额上。191 全量读数如下；分润基数只作对照，不参与定档：
