## 6) A1 回归 CI 化评估与落地（部分阻塞，已如实记录）

- 评估结论：全套都能上云，无必须保留本地的项。GitHub Actions ubuntu runner
  免费额度内可完成：生产口径 build（约 1 分钟）、audit-online（打生产域）、
  演示构建 + 自起服务 + chromium headless shell 安装（约 1–2 分钟）+ run-all
  全套 231 项。成本为零（公开额度/免费分钟内），不引入任何付费服务。
- 落地物：`.github/workflows/regression.yml` 双 job——
  build-online（生产口径构建 + audit-online）与 demo-regression（装 chromium、
  演示构建、自起 3100 服务、跑全套），push main / PR / 手动均可触发。
- **阻塞点（本轮无法绕过）**：推送该文件被 GitHub 拒绝——当前 gh 令牌 scopes
  为 `gist, read:org, repo`，缺 `workflow`，OAuth 应用无权创建 workflow 文件。
  补 scope 需账号持有人在浏览器走一次设备授权确认，属老板账号操作，本轮不代办。
- 处置：workflow commit（`efeafb9`）已转存本地分支 `ci-workflow`，main 保持
  可正常推送；云端通过记录本轮无法产生（workflow 尚未进仓，Actions 无从触发），
  不以本地全过冒充云端通过。
- 解阻塞一步（老板有空时任选其一）：
  1. 在本机终端跑 `gh auth refresh -h github.com -s workflow` 并在浏览器确认，
     然后 `git push origin ci-workflow:main`，push 后 Actions 自动首跑；
  2. 或在 GitHub 网页仓库内新建 `.github/workflows/regression.yml`，
     内容从本地分支 `ci-workflow` 的同名文件粘贴提交。
  启用后把首跑链接回填本节。
